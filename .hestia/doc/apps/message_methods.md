# apps-conductor Message Methods

**Target Conductor**: apps-conductor
**Source**: Design specification §9.7 (around lines 2379-2381), §14 (around lines 3492-3630)

## Transport

All communication uses agent-cli native IPC. Peer name: `apps`.

## apps.* Method List

### Build Flow

| Method | Direction | Description |
|---------|-----------|-------------|
| `apps.build.v1` | Request | Execute cross-compilation build |
| `apps.flash.v1` | Request | Write firmware to target device |

### Testing

| Method | Direction | Description |
|---------|-----------|-------------|
| `apps.test.v1` | Request | Execute test (SIL / HIL / QEMU mode selection) |

### Analysis

| Method | Direction | Description |
|---------|-----------|-------------|
| `apps.size.v1` | Request | Get binary size report (per-section sizes) |

### Debugging

| Method | Direction | Description |
|---------|-----------|-------------|
| `apps.debug.v1` | Request | Bridging with debug-conductor (§10) (start GDB session) |

### conductor-core Common

| Method | Direction | Description |
|---------|-----------|-------------|
| `system.health.v1` | Request | Health check |
| `system.readiness` | Request | Readiness check |

## Upstream and Downstream Integration

- **Upstream (hal-conductor §8)**: Import HAL modules generated by hal-conductor (C headers / Rust crates / Python modules) via `[hal] import = "..."`
- **Cross-cutting (debug-conductor §10)**: Perform flash writing / RTT logging / GDB sessions via debug-conductor
- **Testing**: Supports 3 modes: SIL (QEMU) / HIL (physical device + debug-conductor) / cross-testing (QEMU + cycle-accurate co-sim)
- **CI/CD**: Reproducible builds on GitHub Actions / GitLab CI via shared services layer / CI/CD API (§13)
- **ai-conductor integration**: ai-conductor (§3) supports automatic generation of apps.toml from application specifications (Spec-Driven)
